Bring this project's existing AT Protocol Spaces functionality up to date with the November 12, 2026 alpha release. This release settles the names and shapes of the Spaces API ahead of beta. Many methods, fields, and errors are renamed, notification registration moves into credential requests, and MACs move to HTTP Message Signatures with an HPKE-derived secret. Make the smallest changes needed for compatibility. A dependency update, a set of renames, or a verified no-op can be the complete result.

New errors: importRepo answers `InvalidRepoFile` for a malformed archive and `RepoMismatch` for another account's repo. importSpaceMeta answers `InvalidSpaceMeta` for a malformed archive. authorizeSpaceSync answers `RegistrationNotConfirmed` (section 4). The reference PDS answers `UpstreamFailure` when a managing app fails (section 2b). Generic error handling needs no change.

1d. Encoding. getRepo and exportSpaceMeta respond with, and importRepo and importSpaceMeta require, `Content-Type: application/vnd.dasl.star` in place of `application/octet-stream`. The bytes are unchanged. Update clients that set or check this content type.

1e. Space meta archives. Each `writer/{did}` value now holds `repoRev` in place of `rev`:

    writer/<did>  → { "repoRev": "<TID>", "data": <32 bytes>, "spaceRev": "<TID>" }

Archives exported before this release no longer import. Re-export them from an upgraded host. exportSpaceMeta leaves writers removed from the writer set out of the archive. Implementers reading or writing this profile: rename the key, and reject `rev`.

2. Update policy methods.

2a. Member lists. putMembers takes `{ space, members: [{ did, read, write }] }` and removeMembers takes `{ space, dids: [did] }`. Each takes up to 100 entries and applies them in a single commit. A DID listed twice in putMembers takes its last entry. removeMembers ignores DIDs that are not members, and leaves them in the writer set. The member object moves to `com.atproto.memberspace.defs#member`, and listMembers returns that type. Replace per-member loops with batches only where it is a direct substitution. Otherwise send one-element arrays.

As before, removeMembers and putMembers with `write: false` also remove the account from the writer set, and this is now announced to syncers (section 7). Under a `memberspace` with `publicWrite`, a member whose `write` is false is no longer tracked as a writer. Space hosts implementing memberspace should match.

2b. Managing apps. Serve `com.atproto.managedspace.checkAccess` instead of checkUserAccess:

    GET /xrpc/com.atproto.managedspace.checkAccess?space=<space URI>&repo=<did>&clientId=<OAuth client_id>
    → { "read": true, "write": false }

- `repo` replaces `user` and is now optional. `access` is gone: a single call answers both `read` and `write`, and the authority uses whichever it needs.
- `clientId` is the attested client, a URI, sent when the request presented a client attestation. A check prompted by a write carries none, since `notifyRepoUpdate` doesn't identify the app.
- Without a delegation token, a managed space now asks the managing app with no `repo`, rather than refusing outright. Answer `read: true` there only for spaces meant to be publicly readable.
- The authority's service auth carries `lxm=com.atproto.managedspace.checkAccess`. Update any `lxm` check.
- `managingApp` must be a `did#serviceId` reference. createSpace and updateSpace reject a bare DID. A space already stored with a bare DID can't reach its managing app, so update its policy.
- When the managing app can't be resolved, errors, or doesn't answer within 10 seconds, the reference space host now fails with `UpstreamFailure` rather than denying access. authorizeSpaceSync issues no credential, but leaves its notify registration in place, and a repo host retries its `notifyRepoUpdate` rather than dropping it. This replaces the October 29 behavior of denying on failure.

2c. `memberspace.policy`'s `allowedApps` entries are now validated as URIs. Existing OAuth client IDs already are.

3. Update space type declarations and OAuth scopes.

- A space type declaration's `name` and `name:lang` are renamed `title` and `title:lang`, and `title` is now optional. Rename them in any space type Lexicon the project publishes or vendors, and republish it. A leftover `name` is ignored, so the consent screen would show the NSID instead.

        { "type": "space", "key": "any", "title": "AtmoBoards Forum", "collections": [...] }

- The named scope parameter `type` is renamed `spaceType`: `space?spaceType=com.example.forum&authority=*`. The positional form `space:com.example.forum?authority=*` is unchanged, and permission sets already used `spaceType`.
- Tools that consume space declarations: show `title`, falling back to the NSID.

4. Authorize space sync, and register for notifications through it.

4a. Credentials. getSpaceCredential is renamed `com.atproto.space.authorizeSpaceSync`. Its input is `{ space, credentialKey, delegationToken?, clientAttestation?, notify? }`. Its output adds `spaceRev`, the space's current revision, which is omitted before the space's first update. Calling it again before the credential expires is now called reauthorizing. It works the same as renewing. authorizeSpaceSync answers `SpaceDeleted` for a deleted space before checking the request's authorization.

4b. Registration. registerNotify and unregisterNotify are removed. A syncer registers by including `notify` in authorizeSpaceSync:

    POST /xrpc/com.atproto.space.authorizeSpaceSync
    { "space": "<space URI>", "credentialKey": "did:key:zDna...", "delegationToken": "eyJ...",
      "notify": { "endpoint": "https://syncer.example.com", "token": "<opaque secret>" } }

- `endpoint` is a base URL that the space host calls XRPC methods against (`POST {endpoint}/xrpc/com.atproto.space.notifySpaceUpdate`). The reference PDS fetches it with SSRF protection, so it must be HTTPS on a public address unless the PDS runs in dev mode.
- `token` is an opaque secret of at most 512 characters, such as 32 random bytes in base64. Use a different token for each space, and keep it stable across authorizations.
- A registration is identified by its endpoint and token together. Each authorization carrying the same pair renews it. A different token creates a separate registration.
- These calls carry no service auth. The token in the body authenticates them. Syncers that verified service auth on incoming `notifyWrite` calls must instead check that the token is one they issued for that space, and reject anything else.
- Before creating a new registration, the space host calls `com.atproto.space.confirmRegistration` on the endpoint with `{ space, token, challenge }`. The syncer checks that it issued that token for that space and responds `{ challenge }` with the same value. Otherwise authorizeSpaceSync fails with `RegistrationNotConfirmed`. Renewals are not confirmed again.
- A registration stays active only while the credential from its latest authorization is valid (10 minutes by default). Syncers that want continuous notifications must keep reauthorizing with the same `notify` before the credential expires, even when they have nothing to read.
- An authorization that denies the syncer access to the space withdraws the registration it carries. Other failures do not: an `UpstreamFailure`, or `RepoTakendown` or `RepoDeactivated` while the space authority is suspended. During a suspension the registration lapses but is kept, so the syncer receives `registrationExpired` on the first update after the space resumes.
- Registrations made with registerNotify are not carried over. A syncer re-registers by including `notify` on its next authorization.

4c. Notifications. The space host sends syncers `com.atproto.space.notifySpaceUpdate`, with input `{ space, token, update }`. `update` is one of:

| `update`                                                                            | Replaces                | Syncer action                                                                                                                             |
| ----------------------------------------------------------------------------------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `com.atproto.space.defs#repoWrite { repo, repoRev, data, spaceRev, prevSpaceRev? }` | forwarded `notifyWrite` | As before: sync the repo from its host.                                                                                                   |
| `com.atproto.space.defs#repoRemoved { repo, spaceRev, prevSpaceRev? }`              | new                     | Section 7.                                                                                                                                |
| `#spaceDeleted {}`                                                                  | `notifySpaceDeleted`    | Reauthorize. Only a `SpaceDeleted` answer confirms the deletion and means dropping the space's data. Don't drop data on the notice alone. |
| `#registrationExpired { spaceRev }`                                                 | new                     | The registration lapsed. To keep receiving updates, reauthorize with `notify` and catch up through listWriters from the checkpoint.       |

- Match `update.$type` in full. The repo updates are the shared `com.atproto.space.defs#repoWrite` and `#repoRemoved`, also used by listWriters, while the other two are `com.atproto.space.notifySpaceUpdate#spaceDeleted` and `#registrationExpired`.
- Once a registration lapses, the next update to the space is replaced by `registrationExpired`. After that, only a `spaceDeleted` notice is sent until the syncer reauthorizes.
- To unregister, stop reauthorizing and reject the expiry notice with a non-retryable error, such as HTTP 400. Expiry and deletion notices are retried with backoff from 1 minute up to 12 hours, for at least 72 hours. A syncer that still can't be reached is unregistered.
- `repoWrite` and `repoRemoved` delivery is best effort, as before. Detect gaps from `prevSpaceRev`, or by comparing the `spaceRev` from authorizeSpaceSync with the checkpoint, and catch up through listWriters with `cursor`.
- When a space authority's `#atproto_pds` changes, reauthorize with the new host, which re-registers.

4d. Repo hosts. `notifyWrite` is renamed `com.atproto.space.notifyRepoUpdate`. It is now sent only by repo hosts to the space host, with input `{ space, repo, repoRev, data }`, and service auth with `lxm=com.atproto.space.notifyRepoUpdate`. `spaceRev` and `prevSpaceRev` are gone from it. Delivery and retry rules are unchanged.

4e. Space host implementers: rename the methods. Store registrations keyed by space, endpoint, and token, and confirm each new one first. Renew a registration's expiry to the expiry of each credential it is authorized with. Send each sequenced write and removal to active registrations. Replace the next update with `registrationExpired` for a lapsed registration. Deliver expiry and deletion notices reliably, including deletion notices to lapsed registrations. Drop a registration whose syncer rejects its expiry notice, whose credential is revoked, or whose syncer is denied access when reauthorizing with it. Keep registrations while the space authority is taken down or deactivated. Fetch endpoints as untrusted URLs.

5. Update space credential HTTP signatures.

The construction is unchanged, but verifiers now find the signature by its `tag`, not its label. Reference signers now use the label `sig`:

    Signature-Input: sig=("authorization" "atproto-space-audience");tag="atproto-space-credential"
    Signature: sig=:wNmSUA...:

A host receiving a space credential:

- requires exactly one signature with `tag="atproto-space-credential"`, under any label;
- requires its covered components to be exactly `("authorization" "atproto-space-audience")`, in that order;
- if the signature has a `keyid`, requires it to equal the credential's `cnf.kid`;
- if it has an `alg`, requires it to be `ecdsa-p256-sha256`;
- ignores any other parameters, such as `created`.

Signers using `@atproto/space` or `@atproto/lex-space` get this from the dependency update. Hand-written signers may keep their label, since the reference host accepts any. Hand-written verifiers that look up the label `atproto-space-credential` must switch to the tag.

6. Request and verify MACs as HTTP Message Signatures.

MACs are now HTTP Message Signatures (RFC 9421) using `hmac-sha256` (§3.3.3), keyed with an HPKE-exported secret. Both the secret derivation and the headers change. The old and new formats are incompatible in both directions. Do not support the old ones.

6a. Shared secret. Derive `shared_secret` with HPKE secret export (RFC 9180 §6.2), in base mode, with DHKEM(P-256, HKDF-SHA256) (`0x0010`), HKDF-SHA256 (`0x0001`), and the Export-only AEAD (`0xFFFF`):

    // on the syncer
    enc, shared_secret = SendExportBase(author_kem_public_key, info="atproto-mac", exporter_context="", L=32)
    // on the repo host
    shared_secret = ReceiveExportBase(enc, author_kem_private_key, info="atproto-mac", exporter_context="", L=32)

- `enc` is the syncer's ephemeral P-256 public key. It is sent as a compressed `did:key`, while HPKE encodes it uncompressed.
- This produces a different secret from the November 5 derivation for the same keys.
- Prefer an HPKE library that exposes secret export, such as Go's `crypto/hpke`. Otherwise, follow the plain ECDH and HKDF steps in the proposal's "Appendix: Shared secret without HPKE", and check them against the export-only P-256 entry in the RFC 9180 test vectors.
- Derive a new secret for every request, including retries and each page.

6b. Requesting a MAC. Replace `Atproto-Space-Want-Mac` with `Accept-Signature`:

    getLatestCommit, getRepo, listRepoOps:
    Accept-Signature: mac=("atproto-space-commit";sf);keyid="did:key:zDna...";tag="atproto-space-commit"

    getRecord:
    Accept-Signature: mac=("atproto-space-record";sf);keyid="did:key:zDna...";tag="atproto-space-record"

`keyid` is the ephemeral key (`enc`) as a `did:key`. `tag` selects the profile, and the commit profile's tag is `atproto-space-commit`, not the `atproto-space-repo` of earlier drafts. A host ignores a request with any other tag. The label (`mac` above) is the syncer's choice. The request may include `alg="hmac-sha256"`, and no other parameters.

6c. The response. Replace `Atproto-Space-Mac` with a covered header, and a signature over it under the requested label:

    Atproto-Space-Commit: ver=1, repo="did:example:alice", space="at://did:example:forum/space/com.atmoboards.forum/general", rev="3mwcj3b6uak2f", data=:q3J0...=:
    Signature-Input: mac=("atproto-space-commit";sf);keyid="did:key:zDna...";tag="atproto-space-commit"
    Signature: mac=:AAECAwQFBgcICQoLDA0ODxAREhMUFRYXGBkaGxwdHh8=:
    Vary: Accept-Signature

    Atproto-Space-Record: uri="at://did:example:forum/space/com.atmoboards.forum/general/did:example:alice/com.atmoboards.thread/3mwcj3b6uak2f", cid="bafyrei..."

The covered headers are Structured Field Dictionaries, signed with the `sf` flag, so they are canonicalized before signing. The reference PDS exposes the covered header, `Signature-Input`, and `Signature` to browsers through `Access-Control-Expose-Headers`.

6d. Syncers verify the MAC as hosts verify a credential signature (section 5). Require exactly one signature with the profile's tag, covering exactly the profile's header. If it has a `keyid`, require it to match the request. Then:

- Commits: check that the `Atproto-Space-Commit` fields match the commit in the body (or getRepo's STAR metadata), and that `repo` and `space` match the requested repo.
- Records: check that the `uri` matches the request, then compute the CID of the returned record and check that it matches the header's `cid`.
- If verification fails, refresh the author's DID document and retry with a new key.

6e. Repo hosts: require a valid `Accept-Signature` on these methods when called with a space credential. Ignore requested signatures with other tags. Answer `InvalidSpaceMac` if it is missing or malformed, contains more than one request with the profile's tag, requests other parameters, or has an invalid key. Respond as in 6c, with `Accept-Signature` in `Vary`.

7. Handle the writer set and repo lifecycle.

7a. Writer removal is now announced. When removeWriter, removeMembers, or a putMembers revoking write access removes a repo from the writer set, the space host advances the space revision. It sends a `repoRemoved` notification, and listWriters lists the repo as a `com.atproto.space.defs#repoRemoved` entry until it writes again. A later authorized write re-adds it with a `repoWrite`. Each listWriters entry now carries a `$type`. Code that reads `repoRev` and `data` from every entry must branch on it. Syncers: on a removal, stop treating the repo as part of the space. The repo's records remain on its host. Whether the local copy is deleted or only excluded from views follows the project's existing semantics. A repo in the writer set may still be excluded on application grounds.

7b. listRepoOps returns the repo's current commit, with a MAC, on every page. Apply pages until one has no `cursor`, then compare that page's commit `data` with the running set hash, as before. A page has a `cursor` whenever it is full, so the last page may be empty. listRepoOps answers `RepoNotFound` for a repo that has never been written.

7c. Garbage collection. A repo host MAY discard an empty space repo 72 hours or more after it was cleared, and then answer as though it never existed. Syncers treat that the same as an empty repo. A space host MAY drop empty and removed repos from the writer set after 72 hours or more. Neither sends a notification. A syncer whose last seen space revision is more than 72 hours old should therefore list the whole writer set rather than catch up from its cursor, and drop any repo that is missing or removed. The reference PDS does not garbage collect yet.

7d. Space host implementers: sequence removals like writes, and keep listing a removed repo until it writes again or is collected. Leave removed writers out of exportSpaceMeta.

8. Take note of new guidance.

The proposal adds two non-normative sections. They change no wire formats and need no compatibility work. Do not build labeling, moderation, or access control features because of them.

- Moderation ([proposals#132](https://github.com/bluesky-social/proposals/pull/132)). Labels on space data are `com.atproto.label.record` records `{ uri, cid?, val, cts, exp? }`, written into the same space as their subject by a labeler in the writer set. Labels referencing records in another space are ignored. Duplicate `(uri, cid, val)` labels in one repo resolve to the latest `cts`. Space authorities may publish `!takedown` labels, which syncers and apps should respect. Labelers should not publish public labels about records in non-public spaces.
- Access control in applications ([proposals#139](https://github.com/bluesky-social/proposals/pull/139)). A space credential doesn't say which of an app's users may see a space. The app decides from the space's policy and records. Apps must also respect author account status, space authority account status, deleted records, and space deletion, and must sync account status separately (for example from the firehose).

If the project already indexes space label records, or serves space data to users, report notable gaps against this guidance in the summary rather than fixing them unasked.

Error classes follow section 1c, for example `UserNotAuthorizedError` → `AccountNotAuthorizedError`, `NotSpaceOwnerError` → `NotAuthorizedError`, and `BadSpaceMacError` → `InvalidSpaceMacError`.

`@atproto/lex` generated bindings: regenerate them if the project maintains them. Generated space types now call `l.space(key, nsid, collections, options)`, with the key first. Hand-written `l.space(nsid, key, collections, { name })` calls become `l.space(key, nsid, collections, { title })`, and `Space#name` is `Space#title`. String schemas now reject lone surrogates.

`@atproto/space`:

- Errors extend the new `SpaceError` and carry a `code`. `RepoVerificationError` → `SpaceRepoVerificationError`. An invalid KEM key throws `SpaceKemError` in place of `SpaceMacError`. `SpaceMacError`'s code is `InvalidSpaceMac`.
- `verifyCommit`, `verifyRecord`, `verifyCommitMac`, and `verifyRecordMac` throw on failure instead of returning a boolean.
- Renames: `Commit` → `SpaceCommit`, `VerifiedRepo` → `VerifiedSpaceRepo`, `VerifyRepoParams` → `VerifySpaceRepoParams`, `RecordPath` → `RecordPathString`, `serializeRepo` → `writeRepoStar`, `serializeSpaceMeta` → `writeSpaceMetaStar`. `SpaceMetaWriter.rev` → `repoRev`.
- Tokens: `createSpaceToken(type, payload, keypair)` is split into `createDelegationToken({ iss, sub, aud, keypair })`, `createSpaceCredential({ iss, sub, keyId, keypair })`, and `createClientAttestation({ clientId, aud, kid, keypair })`. `SPACE_TOKEN_TYPES.x.typ` → `DELEGATION_TOKEN_TYP`, `SPACE_CREDENTIAL_TYP`, `CLIENT_ATTESTATION_TYP`. `CreateSpaceTokenOpts` is removed. `parseSpaceToken` and `verifySpaceToken` return a token typed by its type.
- Signatures: `createSpaceSig({ authorization, audience, keypair })` and `createSpaceSigHeaders({ ..., keypair })` take the keypair in their options. `createSpaceSigHeaders` returns `{ headers }`.
- MACs: `formatMacRequest` and `parseMacRequest` replace `formatWantMacHeader`, `parseWantMacHeader`, `formatMacHeader`, and `parseMacHeader`. `createCommitMacHeaders(commit, params)` and `createRecordMacHeaders(uri, cid, params)` replace `computeCommitMac` and `computeRecordMac`, taking the parsed `MacRequest` with its decapsulated `sharedSecret` and returning `{ headers }`. `verifyCommit`, `verifyRecord`, `verifyRepoStar`, `verifyCommitMac`, and `verifyRecordMac` take the request's `keyShare` and `sharedSecret` and the response `headers` (`VerifyMacParams`) in place of `sharedSecret` and `mac`. `COMMIT_MAC_TYPE`, `RECORD_MAC_TYPE`, and `MacType` → `COMMIT_MAC_PROFILE`, `RECORD_MAC_PROFILE`, and `MacProfile`. `MAC_HEADER`, `WANT_MAC_HEADER`, and `RECORD_MAC_VERSION` are removed. `MAC_COVERED_HEADER` is new.
- Stricter types: DIDs, space refs, URIs, and TIDs are branded strings (`DidString`, `SpaceRefString`, `SpaceAtUriString`, `TidString`). A commit `rev` must be a TID, and record CIDs are `CborCid`.
- No longer exported: `defs`, `Def`, `formatSetHashElement`, `LTHASH_STATE_BYTES`, `REPO_STAR_TYPE`, `SPACE_META_STAR_TYPE`, `SPACE_TOKEN_TYPES`, `REPO_STAR_LIMITS`, and `SPACE_META_STAR_LIMITS`, and the internal byte helpers. `readRepoStar`, `verifyRepoStar`, `verifyRepoStarFull`, and `readSpaceMetaStar` still apply their limits. Code that passed the limit constants to `readStar` directly should define its own.
- Schemas use `@atproto/lex-schema`. `zod` is no longer a dependency.

`@atproto/syntax`: `AtUri.makeSpace(spaceDid, spaceType, skey, authorDid, collection, rkey)` → `new SpaceRef(spaceDid, spaceType, skey).recordUri(authorDid, collection, rkey)`. `SpaceAtUriParts.author` → `authorDid`. `isSpaceAtUriString` narrows to the new `SpaceAtUriString`. `isSpaceUri` is no longer exported.

`@atproto/oauth-scopes`: `SpacePermission#type` → `spaceType`. `allowsSpace(target, op)` and `assertSpace(target, op)` take the space and the operation as separate arguments. The space can be a space ref string, `{ spaceDid, spaceType, skey }`, or a match reference. `assertSpaceRef` is removed. `LexiconSpace` has `title` and `title:lang`.

`@atproto/crypto`: `hkdfSha256` is replaced by `hkdfExtractSha256` and `hkdfExpandSha256`. `formatDidVerificationMethod()` is new. `@atproto/did` adds `extractKemKey()`.

`@atproto/repo` and `@atproto/car`, only if used directly: `@atproto/repo` is now isomorphic, and its Node-specific APIs are replaced by generic ones, including the `BlobStore` interface. The `BlockMap` constructor takes an iterable of `CarBlock`s, and `forEach`, `addMany`, and `addMap` are removed. `buildCarBlock` is removed. `CidSet.size` is a getter. `zod` is gone from the public interface.

`@atproto/lex-space` (new, optional): a client for spaces built on `@atproto/lex`'s `Client`. It obtains and renews credentials, signs requests, verifies MACs, and offers typed record reads and writes, space management (`SpaceManager`), and repo sync for syncers (`SpaceReader.pullRepo()`). It can register for notifications (the `notifyRegistrationProvider` option) and reports the space's `spaceRev` on each credential, but serving `confirmRegistration` and `notifySpaceUpdate` is up to the project. If you do adopt it, note that `writers()` also yields removed repos as `repoRemoved` entries, and `pullRepo()` returns `{ type: 'empty' }` for a repo its host doesn't have. Policy schemas are exported as `memberspace.policy`, `managedspace.policy`, and `personalspace.policy`. Do not switch SDK families or replace working code to adopt it. If the project hand-rolls the credential and MAC flow on `@atproto/lex`, mention it in the summary as an option.

For worked examples, see `packages/pds/tests/space/notifications.test.ts`, `packages/pds/tests/space/policy.test.ts`, and the tests in `packages/lex/lex-space` in the implementation.

10. Upgrade a deployment of the reference PDS.

Apply this section only to projects that deploy, package, or fork `@atproto/pds` or the `ghcr.io/bluesky-social/atproto:pds-spaces-alpha` image.

- The account-manager database gets `011` (an email auth factor table, merged from atproto's main branch) and `012`. `012` replaces pending space deletion notices, which were queued for registerNotify registrations, with a new syncer notice queue. Pending notices are dropped.
- Each actor store gets `007`–`009`, which run when the store is first opened, like earlier actor store migrations. They drop registerNotify registrations, create the new registration table, and add writer removal tracking. Syncers re-register on their next authorization. Back up both databases before upgrading.
- This branch numbers account-manager migrations differently from atproto's main branch, where the email auth factor is `008`. Don't point an alpha PDS at a database created by a main release, or the reverse.
- No configuration changes are required. Syncer endpoints and managing apps are fetched with SSRF protection. To test with `http://localhost` syncer endpoints, run the PDS with `PDS_DEV_MODE=true` or `PDS_DISABLE_SSRF_PROTECTION=true`. The optional `PDS_ENTRYWAY_API_URL`, `PDS_ENTRYWAY_REQUIRE_SERVICE_AUTH`, and `PDS_DISABLE_IP_RATE_LIMITS` settings arrive from main and are not needed.
- Images are now built from the repository's root `Dockerfile` (`docker buildx bake pds`), not `services/pds/Dockerfile`. This only matters for forks that build their own image.
- Once upgraded, the PDS uses only the new method names, notification flow, credential signature verification, MAC headers, and secret derivation. Syncers, managing apps, account migration peers, and other repo hosts must be upgraded too.

11. Verify and report.

Validate the changed surface in proportion to what this project owns. For a dependency-only or rename-only update, run the available build/typecheck and focused tests, or a smoke check of the existing flow. Do not build an upstream protocol test suite, add a test framework, or provision server infrastructure solely for this migration.

For projects implementing affected protocol behavior themselves, choose regression tests from:

- Renames: the new method names, fields, errors, and STAR content type. Archives with `repoRev`.
- Policies: batched putMembers and removeMembers, last entry wins, ignored non-members. checkAccess with and without `repo`, its `lxm`, and `UpstreamFailure` on failure.
- Registration: confirmation, `RegistrationNotConfirmed`, renewal by reauthorizing, lapse and the `registrationExpired` notice, unregistering by rejecting it, withdrawal when access is denied but not while the authority is suspended, and reauthorizing on `spaceDeleted`.
- Credential signatures: lookup by tag under any label, `keyid` and `alg` checks, and ignored extra parameters.
- MACs: the HPKE secret against RFC 9180's test vectors, both profiles end to end, covered header matching the body, and `InvalidSpaceMac` cases.
- Writer set: `repoRemoved` from removeWriter and member changes, listWriters' `repoRemoved` entries, and re-adding after a write. listRepoOps' commit on every page, and `RepoNotFound` for a never-written repo.

This is a menu, not a required suite for every project.

Apply schema/state migrations only where this project owns affected persisted state, and regenerate only bindings it maintains, using its normal tooling. Run applicable existing checks. Finish with a concise summary of what applied, exact dependency versions changed, validation results, and any necessary migration steps or blockers. Group irrelevant requirements briefly. A no-change result with evidence is valid. Stop once the project's existing functionality is compatible.
