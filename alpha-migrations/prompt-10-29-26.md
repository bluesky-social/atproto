1. Replace `com.atproto.simplespace` with a space `policy`.

A space is now governed by a single `policy` object. It is an open union discriminated by `$type`, which both selects the policy and carries its configuration. The policy-agnostic lifecycle methods move to `com.atproto.space`, and each policy's own methods live in that policy's namespace.

| October 22                                                                                                    | October 29                                        |
| ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| `com.atproto.simplespace.createSpace`                                                                         | `com.atproto.space.createSpace`                   |
| `com.atproto.simplespace.updateSpace`                                                                         | `com.atproto.space.updateSpace`                   |
| `com.atproto.simplespace.getSpace`                                                                            | `com.atproto.space.getSpace`                      |
| `com.atproto.simplespace.deleteSpace`                                                                         | `com.atproto.space.deleteSpace` (shape unchanged) |
| `com.atproto.simplespace.putMember`                                                                           | `com.atproto.memberspace.putMember`               |
| `com.atproto.simplespace.removeMember`                                                                        | `com.atproto.memberspace.removeMember`            |
| `com.atproto.simplespace.listMembers`                                                                         | `com.atproto.memberspace.listMembers`             |
| `com.atproto.simplespace.checkUserAccess`                                                                     | `com.atproto.managedspace.checkUserAccess`        |
| `com.atproto.simplespace.defs` (`publicPolicy`, `memberListPolicy`, `managingAppPolicy`, `open`, `allowList`) | removed                                           |

1a. Baseline policies. Every PDS must support these three:

    { "$type": "com.atproto.personalspace.policy" }

    { "$type": "com.atproto.memberspace.policy",
      "publicRead": false,
      "publicWrite": false,
      "allowedApps": ["<OAuth client_id>"],   // optional
      "publishPolicy": false,
      "publishMembers": false }

    { "$type": "com.atproto.managedspace.policy",
      "managingApp": "did:web:example.com#forum",
      "publishPolicy": false }

- `personalspace` is for data only its owner should see. Only the authority's own account may read, and no other writers are tracked. It has no fields and no methods.
- `memberspace`: with `publicRead`, the authority issues a credential to anyone, with or without a delegation token. With `publicWrite`, it tracks any user's writes. Otherwise it authorizes only members whose entry has `read` or `write` set. When `allowedApps` is set, only those apps may read, judged by the attested `client_id`, so a client attestation is required. When it is omitted, any app may read without one. `allowedApps` does not apply to writes. All booleans default to false.
- `managedspace` defers every user decision, for both reads and writes, to `managingApp` via checkUserAccess. It has no app allow-list: the managing app receives the attested `client_id` on reads and may decide on it. It also never issues a credential without a delegation token.
- Under every policy, the authority's own account is authorized for reads and writes without consulting a member list or managing app.

1b. Lifecycle methods.

- `createSpace` input is `{ spaceType, skey?, policy }`, replacing `readPolicy`, `writePolicy`, and `appAccess`. The output `{ uri }` is unchanged. Errors are `SpaceAlreadyExists` and `UnsupportedPolicy`. `UnsupportedAppAccess` is gone.
- `updateSpace` input is `{ space, policy }`, both required. The policy is replaced wholesale. Omitted fields are no longer left unchanged, so to change one field, read the policy with getSpace and send the full object back. A `policy` with a different `$type` migrates the space and discards the previous policy's state. For example, a memberspace member list is deleted, and migrating back does not restore it. Migration does not re-evaluate the writer set (section 3).
- `getSpace` returns `{ uri, policy }`. It requires OAuth as the space owner with a covering `read_self` grant. A space credential is no longer accepted, so members hosted elsewhere and syncers can't call it. They can read a published policy record instead (section 1e).
- `deleteSpace` only changes namespace.
- OAuth `space:` scope checks are unchanged: `manage=create` for createSpace, `manage=update` for updateSpace and member changes, `manage=delete` for deleteSpace, and `read_self` for getSpace and listMembers.

Convert existing configurations as follows. The reference PDS migrates stored configurations the same way (section 6):

| October 22 configuration                              | October 29 policy                                                   |
| ----------------------------------------------------- | ------------------------------------------------------------------- |
| `managingAppPolicy` for read, write, or both          | `managedspace` with that `managingApp`. Any `allowList` is dropped. |
| Otherwise, `readPolicy: publicPolicy`                 | `memberspace` with `publicRead: true`                               |
| Otherwise, `writePolicy: publicPolicy`                | `memberspace` with `publicWrite: true`                              |
| Otherwise, `memberListPolicy` for read or write       | `memberspace` with that flag false                                  |
| `appAccess: allowList { allowed }` (non-managedspace) | `memberspace` with `allowedApps: allowed`                           |
| `appAccess: open`                                     | Omit `allowedApps`                                                  |

A space meant only for its owner's data (bookmarks, drafts, mutes) can use `personalspace` instead of a memberspace with no members. A mixed configuration, with a managing app on one side and a public or member-list policy on the other, has no exact equivalent: `managedspace` asks the managing app about both, and it doesn't issue credentials without a delegation token. Report such cases to the user rather than silently changing who has access.

1c. Member list methods. `putMember` `{ space, did, read, write }`, `removeMember` `{ space, did }`, and `listMembers` `{ space, limit?, cursor? }` → `{ members: [{ did, read, write }], cursor? }` keep their shapes under `com.atproto.memberspace`. On a space governed by another policy they fail with `PolicyMismatch`. They now also change the writer set (section 3).

1d. Managing apps. Serve `com.atproto.managedspace.checkUserAccess` instead of `com.atproto.simplespace.checkUserAccess`. The parameters `{ space, user, access, clientId? }` and output `{ authorized }` are unchanged. The authority's service auth now carries `lxm=com.atproto.managedspace.checkUserAccess`, so update any `lxm` check. Under `managedspace`, the app is asked about both reads and writes, so an app previously configured on only one side now gets checks for the other side too. `clientId` is the attested client and is omitted on write checks. The reference authority denies access when the app is unreachable or returns an error.

1e. Published policy and member records. `memberspace` and `managedspace` take `publishPolicy`, and `memberspace` also takes `publishMembers`. When a flag is set, the authority's PDS writes that configuration into the authority's own repo in the space and keeps it in sync, so readers sync it like any other record:

| Flag             | Collection                       | Record key       | Value             |
| ---------------- | -------------------------------- | ---------------- | ----------------- |
| `publishPolicy`  | `com.atproto.space.policy`       | `self`           | `{ policy }`      |
| `publishMembers` | `com.atproto.memberspace.member` | the member's DID | `{ read, write }` |

These writes advance the authority's repo and send write notifications as usual, and clearing a flag withdraws the records. The configuration remains the source of truth. Any member can write records of these types to their own repo, so readers treat them as authoritative only in the authority's repo. As a stopgap until Lexicon has a DID record-key format, a did:web with a percent-encoded port is keyed without the encoding (`did:web:localhost%3A2583` → `did:web:localhost:2583`). The reference PDS refuses createRecord, putRecord, deleteRecord, and applyWrites to either collection in any repo, with HTTP 400. Code that maintained such records by hand should set the flags instead.

1f. Space hosts. Reject an unimplemented `$type` with `UnsupportedPolicy`. Store the policy with defaults filled in and unknown fields dropped, so that what is stored is what is enforced. Require `managingApp` to be a DID with an optional service fragment. Delete the member list when a space migrates away from memberspace. Serve getSpace to the owner only. Update the policy, member list, and published records together.

2. Handle the changed credential errors.

The reference authority now checks the user before the app. A user the policy does not authorize gets `SpaceNotFound` (HTTP 400) instead of `UserNotAuthorized`, so a refusal discloses nothing about the space. `AppNotAuthorized` is only returned once the user passes, so a non-member using a disallowed app now gets `SpaceNotFound`. Without a delegation token, only a `memberspace` with `publicRead` issues a credential; any other space answers `SpaceNotFound`, as before. `SpaceDeleted` is unchanged.

Clients that branched on `UserNotAuthorized`, for example to show "you're not a member", must treat `SpaceNotFound` as "not found or not authorized". `UserNotAuthorized` and `NotAuthorized` remain in the Lexicon, and other authorities may still return them, so keep handling them. Authority implementers may answer `SpaceNotFound` in place of `UserNotAuthorized`.

3. Remove accounts from the writer set.

New host method `com.atproto.space.removeWriter`:

    POST /xrpc/com.atproto.space.removeWriter
    Content-Type: application/json

    { "space": "<space URI>", "did": "<writer DID>" }

It requires OAuth as the space owner with `manage=update` and returns no body. It is idempotent. Errors are `SpaceNotFound` and `NotSpaceOwner`. The account disappears from listRepos, and is tracked again if it later makes a write the policy authorizes.

- `memberspace.removeMember`, and `putMember` with `write: false`, now also remove the account from the writer set.
- Nothing else does. `updateSpace` does not re-evaluate the writer set, and a `managedspace` authority doesn't learn when the managing app revokes someone. Projects that manage such spaces call removeWriter themselves wherever they already revoke write access.
- Removal is not announced to syncers, and it doesn't touch the account's records, which remain on its repo host. Don't add new reconciliation for it unless the project already prunes its local writer list from listRepos.
- Space hosts: implement removeWriter with the authorization above, and drop writers on member removal and write revocation.

4. Clear a space repo with `clearRecords`.

New PDS method `com.atproto.space.clearRecords`:

    POST /xrpc/com.atproto.space.clearRecords
    Content-Type: application/json

    { "space": "<space URI>", "repo": "<authenticated DID>" }   → {}

It deletes every record in the caller's repo in the space, along with their blob references. It then clears the repo's operation log, advances the repo to a new `rev`, and sends a write notification to the space host. The new `data` is the empty repo's digest, `e5a00aa9991ac8a5ee3109844d84a55583bd20572ad3ffcd42792f3c36b183ad`. The exception is the authority's own repo, where published `com.atproto.space.policy` and `com.atproto.memberspace.member` records are kept and the digest covers them.

`repo` must be the authenticated account. With OAuth, the caller needs a `delete` grant for every collection the repo holds records in, apart from the kept collections. Clearing a repo with nothing to delete succeeds as a no-op, with no new revision and no notification. The PDS applies its usual write rate limits.

The repo is cleared, not deleted. It stays in the writer set at the empty digest, and a later write repopulates it. Clearing does not delete the space; an authority still uses deleteSpace for that. Projects that delete a user's data in a space record by record may switch to clearRecords, but don't have to.

Syncers: after a clear, listRepoOps from an earlier `since` returns the new commit with no ops, and its `data` won't match the local running hash. Treat that mismatch as the signal to resync from getRepo, replacing the local copy and removing records absent from the archive, as the October 22 release already describes. Do not drop local records based on an unauthenticated `data` value from notifyWrite or listRepos alone.

Repo hosts: implement clearRecords as above, in one transaction. A host may garbage-collect an empty repo once the clear has had time to propagate, and then answer as though the repo never existed. The reference PDS does not currently do this.

5. Migrate space data along with an account.

5a. Migration tools. Do the usual account migration steps, including the `atproto_kem` handling from the October 22 release, and then:

1. On the old host, list the account's spaces with `com.atproto.space.listSpaces`, following `cursor`. The list includes spaces the account is the authority of (those whose URI names the account's DID), as well as spaces it holds a repo in.
2. For each space the account is the authority of, download `com.atproto.space.exportSpaceMeta?space=<space URI>` from the old host and POST the bytes to `com.atproto.space.importSpaceMeta` on the new host, with `Content-Type: application/octet-stream`. This must happen before importing the account's own repo in that space; otherwise importRepo answers `SpaceNotFound`.
3. For each space the account holds a repo in, download the repo with `com.atproto.space.getRepo` from the old host and POST the STAR bytes to `com.atproto.space.importRepo` on the new host. This is an OAuth read of the account's own repo, so no MAC is needed. Then copy its blobs: `com.atproto.space.listBlobs` and `com.atproto.space.getBlob` on the old host, and `com.atproto.repo.uploadBlob` on the new host. The new host makes a blob permanent when an imported space record references it.

Both imports replace whatever the new host holds for that space or repo, so a failed step can be retried. Auth matches `com.atproto.repo.importRepo`: a full-access session (not an app password), or OAuth. With OAuth, importRepo needs a `create` grant for every collection in the archive, and importSpaceMeta needs `manage=create` and `manage=update` for the space. An archive containing anything the scope doesn't cover is rejected as a whole. The new host must be accepting imports, and its maximum import size applies to both bodies. Notification registrations, credential revocations, and deleted-space tombstones are not carried over.

5b. Space meta archive. This is a STAR file, framed like getRepo's, with the `atproto-space-meta` profile. The metadata and all values are DRISL:

    metadata: { "$type": "atproto-space-meta", "ver": 1, "space": "<space URI>" }

    policy                                         → the policy object
    com.atproto.memberspace.member/<did as rkey>   → { "$type": "com.atproto.memberspace.member", "read": true, "write": false }
    writer/<did>                                   → { "rev": "<TID>", "data": <32 bytes>, "spaceRev": "<TID>" }

The body has three sections, in this order:

- A single `policy` key.
- Policy state, keyed like record paths. Among the baseline policies, only memberspace has any: its member list.
- One `writer/{did}` key per writer-set entry.

Within each section, keys are in strict bytewise order with no duplicates. Importers reject:

- a parse error or a missing `policy`;
- a section or key out of order, or a duplicate key;
- an unimplemented policy (`UnsupportedPolicy`);
- any policy-state key the policy doesn't define. Never silently drop access state.

The writer entries keep their `spaceRev`, so listRepos cursors stay valid after migration.

5c. Syncers. A migrated repo shows up on the new host at a new `rev` with unchanged `data`. The new host's operation log starts empty, so listRepoOps from an old `since` returns no ops and a commit whose `data` still matches; just advance the checkpoint. The space host moves with its authority's `#atproto_pds`, but registrations don't move with it. Syncers that hold registrations should re-register with the new host when the authority's identity changes, or at their next renewal, and catch up through listRepos from their checkpoint.

5d. Implementing the imports and export.

importRepo, on repo hosts:

- Read the STAR archive without a MAC, and check that the records fold to the commit's `data`.
- Require the commit's `repo` to be the authenticated account, and require the space to exist if the account is its authority.
- Re-encode each record, and reject any whose DRISL encoding doesn't match its CID.
- Give the repo a new `rev` with the same `data`, replacing any prior records, operation log, and blob associations in one transaction.
- Import published policy and member records as they are. The direct-write refusal from section 1e does not apply.

exportSpaceMeta and importSpaceMeta, on space hosts:

- exportSpaceMeta requires OAuth as the space owner with `read_self`.
- importSpaceMeta requires the space to be anchored on the authenticated DID, failing with `NotSpaceOwner` otherwise, and fails with `UnsupportedPolicy` for an unimplemented policy.
- Serialize and validate the archive as in section 5b.
- Importing doesn't republish records, since they arrive with the authority's repo.

6. Upgrade a deployment of the reference PDS.

Apply this section only to projects that deploy, package, or fork `@atproto/pds` or the `ghcr.io/bluesky-social/atproto:pds-spaces-alpha` image. No configuration or environment variables changed, and the account-manager database has no new migrations.

It creates `space_policy` and converts each `simplespace_config` row to a baseline policy, as in the table in section 1b. It deletes the member lists of spaces that become `managedspace`. It drops `simplespace_config`, and renames `simplespace_member` to `memberspace_member`. Migrated spaces publish nothing, since `publishPolicy` and `publishMembers` are false. Back up actor stores before upgrading.

- The new import methods respect the existing `PDS_ACCEPTING_REPO_IMPORTS` and `PDS_MAX_REPO_IMPORT_SIZE` settings.

Wholesale replacement on updateSpace, and discarding the member list on a `$type` change. getSpace refusing a space credential. `PolicyMismatch` from member methods. The authority always being authorized.
- Published records: records created, updated, and withdrawn as the flags, members, and policy change. Direct writes refused in any repo.
- Managing apps: the new NSID and `lxm`. Read and write checks. `clientId` only on reads. Denial on failure.
- Credentials: `SpaceNotFound` for an unauthorized user. The user checked before the app. Credentials without a delegation token only under `publicRead`, with `allowedApps` still enforced.
- Writer set: removeWriter limited to the owner and idempotent. Removal on removeMember and on `putMember` with `write: false`. Re-tracking after an authorized write.
- clearRecords: `delete` grants per collection. Published records kept in the authority's repo. The empty digest. A no-op on an empty repo. The write notification. Syncer resync after a clear.
- Migration: an exportSpaceMeta → importSpaceMeta → importRepo round trip. importRepo before importSpaceMeta failing with `SpaceNotFound`. Retrying an import. Rejecting unknown policies, unknown policy state, and out-of-order keys. Scope checks on imports. A new `rev` with unchanged `data`. Blob permanence on upload.

This is a menu, not a required suite for every project.
