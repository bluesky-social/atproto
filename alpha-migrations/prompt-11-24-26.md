Bring this project's existing AT Protocol Spaces functionality up to date with the November 24, 2026 alpha release. Changed Lexicons:

- Added: `com.atproto.server.reserveKemKey`.

1. Move space URIs to `at:space/`.

1a. The form. The `space` path marker is gone, and `space/` replaces the `//` authority:

    November 12:  at://{spaceDid}/space/{spaceType}/{skey}[/{authorDid}/{collection}/{rkey}]
    November 24:  at:space/{spaceDid}/{spaceType}/{skey}[/{authorDid}/{collection}/{rkey}]

    at:space/did:example:forum/com.atmoboards.forum/general
    at:space/did:example:forum/com.atmoboards.forum/general/did:example:alice/com.atmoboards.thread/3mwcj3b6uak2f

- A space URI references either a space (through `skey`, the `space-ref` format) or a record in a space (through `rkey`). No other lengths are valid.
- `spaceDid` and `authorDid` must be DIDs. Neither may be a handle.
- Public URIs (`at://{did}/{collection}/{rkey}`) are unchanged. There is no `at://` form of a space URI.
- Both forms are valid under the `at-uri` format. A space URI is told apart from a public one by its `at:space/` prefix.

1b. Where it appears. Hosts now emit only the new form, in:

- the `space` parameter or field of every `com.atproto.space.*`, `com.atproto.memberspace.*`, and `com.atproto.managedspace.checkAccess` method, including `notifyRepoUpdate`, `notifySpaceUpdate`, `confirmRegistration`, and the entries of `listSpaces`;
- the record `uri`s returned by the record methods;
- the `sub` of delegation tokens and space credentials;
- the `space` in the `Atproto-Space-Commit` MAC header, and the `uri` in the `Atproto-Space-Record` MAC header;
- the `space` in the metadata of both STAR profiles (getRepo and importRepo, exportSpaceMeta and importSpaceMeta).

The reference PDS and the SDKs accept only the new form in all of these. Token `sub`s are compared exactly, so a delegation token or credential minted by a host that hasn't upgraded fails against one that has. Archives exported before this release no longer import. Re-export them from an upgraded host.

Unchanged: OAuth `space:` scopes (they name a space type and authority, not a URI), record CIDs, and commit `data` (the set hash covers only collection, rkey, and CID). Synced data stays valid, and syncers don't need to resync.

1c. Stored URIs and comparisons. Old-form URIs in the project's own state no longer match what hosts send.

- Rewrite stored space URIs and refs to the new form, with the project's normal migration tooling. This covers database keys and columns, caches, config, fixtures, and test data. Write the rewrite so it only touches values still in the old form, and it can safely run again. The reference PDS's rewrite is in `packages/pds/src/db/rewrite-space-uris.ts`.
- References the project extracted from record values into its own tables, such as reply parents and backlink or reference indexes, are project state too. Rewrite them along with keys, or backlinks to alpha-era records stop matching. If the project reads references straight out of stored record JSON, normalize them at query time instead.
- Where stored values can't be rewritten, normalize them where they enter the project. In TypeScript, `new AtUri(x).toString()` (or `SpaceRef.for(x).toString()` for a space) reads either form and prints the new one. Never compare raw strings across the two forms.
- Update code that builds or splits space URIs by hand, such as concatenation with `/space/`, checks for a `space` segment, and fixed segment indexes. After the prefix, the first segment is the space DID.
- Routes and links that embed space URIs should generate the new form. Accept the old form only where existing links must keep working.

1d. Record values. Record values are not migrated, since rewriting them would change their CIDs. Records written during the alpha may still embed old-form URIs, such as a reference to a space or to another record in a space. This applies only to the values themselves. References the project extracted from them are covered in 1c.

- Lenient validation (`strict: false`) accepts both forms. Strict validation, the default, accepts only the new form.
- Read leniently, write strictly. Validate space records read from hosts leniently, normalize embedded URIs before comparing or indexing them (including references written to backlink or reply indexes), and write only the new form. `SpaceClient` and `SpaceReader` already validate the records they read leniently.
- Lenient validation also relaxes `datetime` and `record-key` checks. Don't use it on input from the project's own users.
- The reference PDS validates params strictly, and records strictly only for record types it has schemas for. It won't stop the project from writing old-form URIs in its own record types, so make sure it doesn't.
- Support for the old form is temporary and will be removed before beta. Don't add new uses of it.

1e. Implementers in other languages. Detect a space URI by its `at:space/` prefix. The authority runs to the next `/` and must be a DID. It is followed by `spaceType` and `skey`, then optionally by `authorDid`, `collection`, and `rkey`. Validate each part as before. Validators that require `//` after the scheme must also accept the `at:space/` form for `at-uri`. The `space-ref` format admits only the three-segment `at:space/` form. Emit only the new form. Accept the old form only when leniently reading record values written during the alpha, and never in params, tokens, MAC headers, or archives.

2. Use a full session or OAuth for spaces.

Space methods now refuse sessions created with an app password, including privileged app passwords, with `InvalidToken` ("Bad token scope"). This covers every space method an account calls with its own session: record reads and writes, blobs, `getRepo`, `getLatestCommit`, `listRepoOps`, space management (`createSpace`, `getSpace`, `updateSpace`, `deleteSpace`, `listSpaces`, `removeWriter`), member lists (`putMembers`, `removeMembers`, `listMembers`), archives (`exportSpaceMeta`, `importRepo`, `importSpaceMeta`), and `getDelegationToken`, which already refused them. Requests authenticated by a space credential, delegation token, or service auth are unaffected, including `authorizeSpaceSync`, `listWriters`, the notification methods, and credential reads of other repos.

Apps should use OAuth with `space:` scopes. Scripts, bots, and tests can log in with the account password through `createSession` instead. If the project only used an app password for a script or test, switch that to a full session rather than adding OAuth.

3. Update library calls (npm).

Apply only to symbols the project already uses.

3a. `@atproto/syntax`:

- `AtUri` and `SpaceRef` print the new form. `new AtUri()` and `SpaceRef.for()` read either form. `SpaceRef.parse()` reads only the new form, so use `SpaceRef.for()` on stored or embedded values.
- `isAtUriString()`, `assertAtUriString()`, `isSpaceAtUriString()`, and `isSpaceRefString()` accept only the new form by default, and both forms with `{ strict: false }`. `isSpaceRefString()` gains that options argument. The deprecated `isValidAtUri()` and `ensureValidAtUri()` are lenient, so they accept both.
- `SPACE_MARKER` is removed. `SPACE_URI_PREFIX` (`'at:space/'`) is new.
- On a space URI, `origin` is `at:space/{spaceDid}`, `host` is still the space DID, and `pathname` now starts at the space type.
- `new AtUri()` throws on a space URI that isn't valid in full, such as one with a handle as its authority.
- `fromLegacySpaceUri()` is new and temporary. It rewrites an old-form string to the new form, and returns `undefined` for anything else.
- `AtUri` now parses `did:web` authorities containing `_`.

3b. `@atproto/lex-schema` and `@atproto/lex`: the `at-uri` and `space-ref` formats follow 3a. Strict validation, the default, accepts only the new form, and `strict: false` accepts both. `isSpaceRefStringLenient()` is new.

3c. Space type declarations and codegen:

- `l.space(key, spaceType, collections)` takes the collections' record schemas, or `l.typedRef(() => …)`s to them, instead of NSID strings. Its options argument (`title`, `title:lang`, `description`) is removed, along with `Space#title`, `Space#options`, and `SpaceOptions`. `Space#nsid` is now `Space#spaceType` (also `$spaceType`), `Space#type` is `'space'`, and the type parameters are `Space<TKey, TSpaceType, TRecord>`, key first. A hand-written `l.space(key, nsid, ['com.example.post'], { title })` from the November 12 prompt becomes `l.space(key, nsid, [com.example.post.main])`.
- `typedUnion()` accepts record schemas directly, without `l.typedRef()`.
- Regenerate bindings the project maintains. Generated space schemas reference the generated record schemas of their collections, and export the space type's NSID as `$spaceType` (for example `com.example.forum.$spaceType`).
- `lex build` fails if a space type lists a collection that isn't a record. `lex install` now installs a space type's collections as its dependencies. Every collection a space type Lexicon lists must be a record Lexicon that consumers can resolve, or their install fails. Check this for any space type Lexicon the project publishes.

3d. `@atproto/lex-space`:

- The typed record helpers take a collection NSID or a built record instead of a schema: `get(com.example.post.$type, { rkey })`, `delete(com.example.post.$type, { rkey })`, `list(com.example.post.$type)`, `listAll(com.example.post.$type)`, `create(com.example.post.$build({ text }))`, and `put(com.example.post.$build({ text }), { rkey })`. The `applyWrites()` helper follows the same rules: `op.create(record)`, `op.update(record, { rkey })`, `op.delete(collection, { rkey })`, and `op.getSchema(collection)`. Operations built by hand are still accepted.
- These helpers accept only the collections the space type declares, and always validate against the space type's schema of the collection. `validateRequest: false` no longer lets other collections through. Use `createRecord()`, `putRecord()`, and `deleteRecord()` for those.
- `list()` and `listAll()` are now on `SpaceReader`, where `repo` is required.
- `records()`, `allRecords()`, `list()`, and `listAll()` flag each record with `valid`, and give the reason in `error` when it is `false`. A record is valid only if its collection is declared by the space type, matches the record's `$type`, and the record matches the space type's schema of that collection. `records()` no longer accepts `collection` or `excludeValues` (use `listAll()` or `listRecords()`), and `allRecords()` no longer accepts `collections`.
- Types: `SpaceCollectionSchema<S, T>` is removed in favor of `SpaceCollection<S>`, `SpaceRecordSchema<S, C>`, and `SpaceRecordInput<S, C>`. `SpaceReader.AllRecordsSchemaItem<T>` is replaced by `SpaceReader.AllRecordsItem<S>`.
- `openSpace()` and `createSpace()` also accept the space type's namespace (`com.example.forum`) in place of its `main`.
- `SpaceClient` and `SpaceReader` validate the records they read leniently (section 1d).
- `SpacePolicyManager#updatePolicy()` throws `UnsupportedSpacePolicyError` when the space's policy type changed since the manager was opened, instead of switching the space back to its cached policy.
- A `SpaceReader` running on a server should be given an SSRF-protected `fetch`, since the hosts it contacts are named by DID documents. If a server-side reader uses the global `fetch`, note it in the summary.

3e. `@atproto/lex-client`, used by `@atproto/lex` and `@atproto/lex-space`:

- An `atproto-proxy` header passed in a request's `headers` no longer sets that request's `service`. Pass `service` in the request options instead.
- `validateRequest: false`, the `Client` default, now also skips validating params and applying their defaults. Params are sent as given.
- Invalid records yielded by `Client.list()` and `Client.listAll()` include the validation `error`.

3f. `@atproto/api`:

- The `com.atproto.space`, `memberspace`, `managedspace`, and `personalspace` namespaces are back. They were missing from the first November 12 build. `com.atproto.server.reserveKemKey` is new.
- `@atproto/lexicon`, which `@atproto/api` validates with, accepts only the new form and has no lenient mode. If the project validates alpha-era space records with it, records embedding old-form URIs fail. Note this in the summary rather than switching SDK families.

3g. `@atproto/oauth-scopes`: `allowsSpace()` and `assertSpace()` accept `collection: '*'` for `create`, `update`, and `delete` checks. Only a grant covering every collection matches it.

4. Handle account migration, archives, and KEM keys.

4a. Activation. Without an entryway, `com.atproto.server.activateAccount` now requires the account's DID document to publish the `#atproto_kem` key the PDS holds for it. Otherwise it fails with "DID document verification method does not match expected KEM key". `did:web` accounts may omit the key. Tools that copy `verificationMethods` from `getRecommendedDidCredentials` into the PLC operation already do this, since `submitPlcOperation` has checked it since October 22. Tools that build their own operation, or update a `did:web` document that already lists the key, must carry the new PDS's `atproto_kem` through.

4b. Space archives. `com.atproto.space.importRepo` now requires full access to the space (`read`, plus `create`, `update`, and `delete` on every collection) rather than `create` on the archive's collections, and refuses app passwords (section 2). It indexes only the difference from what the host holds. Unchanged records stay, and blobs of removed records are released. As before, the op log is cleared and the repo is reset to a new rev. Archives exported before this release carry old-form URIs and no longer import (section 1b).

4c. `com.atproto.server.reserveKemKey` (new) is the KEM counterpart to `reserveSigningKey`. It takes `{ did? }` and returns `{ kemKey }`, a `did:key`. An entryway can reserve a KEM key and publish it in a genesis PLC operation before the account exists. Behind an entryway, `createAccount` uses the reserved key when the operation includes one, and otherwise generates a key that it leaves unpublished. Most projects don't need this.

5. Upgrade a deployment of the reference PDS.

Apply this section only to projects that deploy, package, or fork `@atproto/pds` or the `ghcr.io/bluesky-social/atproto:pds-spaces-alpha` image.

- The account-manager database gets `013`, which rewrites space URIs in the notification retry queues and the revoked credential table.
- Each actor store gets `010` and `011` when it is first opened. `010` remodels the space tables. It drops `space.authority`, `space_record_oplog.action`, `space_record_oplog.uri`, and the `space_record_rev_idx` index, and adds a partial `space_type_idx`. `011` rewrites stored space URIs. Record values are left as they are (section 1d).
- The URI rewrites only touch values still in the old form, so a run that stops part-way finishes when it runs again.
- Back up both databases before upgrading. Each migration has a `down()`, but don't roll the image back after upgrading. `010` drops columns, so an older alpha release can't write spaces against an upgraded actor store.
- As before, this branch numbers migrations differently from atproto's main branch and from `permissioned-data`. Don't move a database between them.
- Space writes, including member list changes and `removeWriter`, now count against their own `space-write-hour` (5,000 points) and `space-write-day` (35,000 points) limits, separate from public repo writes. Creates cost 3 points, updates 2, and deletes 1. Inbound `notifyRepoUpdate` is limited per writer to 1,500 an hour and 10,000 a day, and the writer's host retries.
- Space queries now read through indexes, so paging through and exporting large spaces is much faster. Large deletes and member list changes no longer fail with "too many SQL variables". No configuration is needed.
- `PDS_TRUSTED_PROXIES` and `PDS_SQLITE_SYNCHRONOUS_FULL` arrive from main. Both are optional and not needed for spaces.
- Once upgraded, the PDS speaks only the new URI form. Syncers, managing apps, account migration peers, and other repo hosts must be upgraded too.

6. Verify and report.

Validate the changed surface in proportion to what this project owns. For a dependency-only or call-site update, run the available build/typecheck and focused tests, or a smoke check of the existing flow. Do not build an upstream protocol test suite, add a test framework, or provision server infrastructure solely for this migration.

For projects implementing affected behavior themselves, choose regression tests from:

- URIs: both lengths round-trip in the new form. Old-form values read leniently and print in the new form. The old form, handles, and other lengths are rejected strictly. Stored keys are found by new-form URIs.
- Records: an alpha-era record embedding an old-form URI reads as valid leniently, and new writes use the new form.
- Auth: app password sessions get `InvalidToken` on space methods.
- lex-space: typed helpers work with collection NSIDs and built records, and reject undeclared collections.
- Migration: activation with and without the KEM key, importRepo with a full grant, and old archives rejected while re-exported ones import.
- Hosts: the new form in params, tokens, MAC headers, and STAR metadata, and the old form rejected in each.

This is a menu, not a required suite for every project.

Apply schema/state migrations only where this project owns affected persisted state, and regenerate only bindings it maintains, using its normal tooling. Run applicable existing checks. Finish with a concise summary of what applied, exact dependency versions changed, validation results, and any necessary migration steps or blockers. Group irrelevant requirements briefly. A no-change result with evidence is valid. Stop once the project's existing functionality is compatible.
