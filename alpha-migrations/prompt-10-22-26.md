1. Request space credentials with a request body, and allow public spaces.

Apply this section to code that calls or serves com.atproto.space.getSpaceCredential.

getSpaceCredential is no longer authenticated by the delegation token or an HTTP Message Signature. Remove the `Authorization: Bearer <delegation-token>` header and the `atproto-space=("authorization");keyid="..."` signature from this request. Everything moves into the JSON body:

    POST /xrpc/com.atproto.space.getSpaceCredential
    Content-Type: application/json

    {
      "space": "<space URI>",
      "credentialKid": "<P-256 did:key>",
      "delegationToken": "<delegation JWT>",
      "clientAttestation": "<client attestation JWT>"
    }

`space` and `credentialKid` are required. `delegationToken` and `clientAttestation` are each optional and sent when the space requires them. Credential clients still generate a fresh ephemeral P-256 keypair for each new credential, send its public did:key as `credentialKid`, and keep the private key for the credential's lifetime. The authority binds the credential with `cnf.kid = credentialKid`.

A space authority may require a delegation token, a client attestation, both, or neither. It MUST NOT reject a request solely because it includes a valid assertion that the space does not require. Clients that already send a delegation token can keep doing so for every space. Do not add a token-less code path unless the project already intends to access public spaces without a user session. A space that requires neither assertion offers public access. Syncers still need a space credential, request signatures (section 2), and MACs (section 4) to read repos.

Errors changed: an invalid delegation token (bad signature, expired, replayed, or wrong audience or subject) returns `InvalidDelegationToken` as an invalid request (HTTP 400). Previously most of these were authentication failures on the Authorization header. Without a delegation token, the reference authority answers `SpaceNotFound` for any space that isn't public, so a token-less request can't learn that the space exists. A deleted space answers `SpaceDeleted` with or without a token. `UserNotAuthorized`, `AppNotAuthorized`, `NotAuthorized`, and `InvalidClientAttestation` are unchanged. Update error handling that branched on 401s or auth error codes for this call.

Authority side: reject a `credentialKid` that is not a P-256 did:key. When `delegationToken` is present, validate it as before (type, issuer signature, audience from section 3, subject equal to the requested space, lifetime, and single-use replay check) and refuse a bad one with `InvalidDelegationToken`. Client attestation validation is unchanged apart from its audience. Credential claims, lifetime, and revocation are unchanged from the October 1 release. In the reference simplespace implementation, a `publicPolicy` read policy issues a credential without a delegation token, an `appAccess` allow-list is still enforced without one, and a deleted space returns `SpaceDeleted` before policy checks. Remove server code that read the delegation token from Authorization or verified a `keyid`-bound signature on this method.

2. Present space credentials with the `Atproto-Space-Credential` scheme and a tagged signature.

Apply this section only to code that sends or validates requests authorized by a space credential. Consumers of a helper should update the helper and its call sites; they do not need their own signing or verification implementation.

|                      | October 1       | October 22                                |
| -------------------- | --------------- | ----------------------------------------- |
| Authorization scheme | `Atproto-Space` | `Atproto-Space-Credential`                |
| Signature label      | `atproto-space` | `atproto-space-credential`                |
| Signature params     | none required   | `tag="atproto-space-credential"` required |

Send:

    Authorization: Atproto-Space-Credential <space-credential>
    Atproto-Space-Audience: <audience DID>
    Signature-Input: atproto-space-credential=("authorization" "atproto-space-audience");tag="atproto-space-credential"
    Signature: atproto-space-credential=:<standard-base64 signature bytes>:

The signed UTF-8 bytes are these lines joined by LF, with no trailing LF:

    "authorization": Atproto-Space-Credential <space-credential>
    "atproto-space-audience": <audience DID>
    "@signature-params": ("authorization" "atproto-space-audience");tag="atproto-space-credential"

The following are unchanged from October 1: the two covered components, in that order. The ecdsa-p256-sha256 algorithm, with a 64-byte r || s signature, rejecting DER and accepting both low-S and high-S. Optional `alg`, which must be ecdsa-p256-sha256 if present. Optional `keyid`, which must equal `cnf.kid` if present. Verification against `cnf.kid`. Audience derivation: the repo owner's DID for repo operations and the space authority's bare DID for space-host operations. Reuse of a signature for the same credential and audience. Any additional signature parameters supplied are part of the signature base as serialized in Signature-Input. With the credential-request signature gone (section 1), `keyid` is no longer required anywhere.

Receiving services require the `tag` parameter to equal `atproto-space-credential`, and find the signature by the new label even alongside other labels. Recognize the scheme regardless of case (`atproto-space-credential` is also accepted), but compute the signature base over the Authorization value exactly as received, with no case normalization. The reference implementation no longer accepts the old `Atproto-Space` scheme or `atproto-space` label. A request using the old scheme gets HTTP 400 `InvalidToken` ("Unsupported authorization type"), not a signature error. Emit padded standard base64 in the Signature byte sequence, per RFC 9651. Parsers should tolerate missing padding, as the reference does. Relevant errors remain BadSpaceSignature and BadSpaceAudience. Regenerate any cached signatures, since their format changed.

3. Resolve space authorities like any other account.

The dedicated `#atproto_space` verification method and `#atproto_space_host` service entry are gone. A space authority's `#atproto_pds` service endpoint is its space host, and its `#atproto` key signs its space credentials and any service auth it sends as the authority. Remove lookups of the dedicated entries, their fallbacks, and their "malformed entry is an error" handling. An authority that published those entries can remove them, because they are now ignored. If they pointed at a different host or key, that role moves to the account's PDS and `#atproto` key.

Token audiences and key IDs:

- Delegation tokens: `aud = <authority DID>#atproto_pds`, previously `#atproto_space_host`. The JWT header `kid` must be exactly `#atproto`.
- Client attestations: `aud = <authority DID>#atproto_pds`, previously `#atproto_space_host`. Their `kid` still identifies the client's own key.
- Space credentials: the JWT header `kid` must be exactly `#atproto`. Verifiers reject any other value, including a missing `kid`, `atproto` without the `#`, or `#atproto_space`.
- Repo host → space host notifyWrite service auth: `aud = <authority DID>#atproto_pds`. The reference receiver also accepts the bare authority DID and no longer accepts `#atproto_space_host`. Notifications forwarded from the authority to registered syncers are unchanged.

4. Authenticate commits and records with MACs, and rename `hash` to `data`.

Commits no longer carry a signature. Instead, the syncer and repo host establish a per-request shared secret, and the repo host returns an HMAC in a response header. A leaked response therefore proves nothing about authorship to a third party.

4a. Commit shape and renames. Replace `com.atproto.space.defs#signedCommit` with `com.atproto.space.defs#commit`:

    // October 1
    { ver, hash, ikm, sig, mac, rev }
    // October 22
    { ver: 1, repo: "<author DID>", space: "<space URI>", rev: "<TID>", data: <32 bytes> }

`data` has the same value as the old `hash`, the sha256 of the LtHash state. Stored digests stay valid; only the field name changes, so do not recompute them. Rename `hash` to `data` in commits (getLatestCommit, listRepoOps, and STAR metadata), in notifyWrite bodies on both hops, and in listRepos entries. `repoRev`, `spaceRev`, `prevSpaceRev`, and pagination are unchanged. Remove handling of `ikm`, `sig`, the in-commit `mac`, and the `atproto-space-v1` context. Commits are no longer verified against the author's `#atproto` signing key.

4b. KEM key. Each account with space repos publishes a dedicated P-256 key in its DID document's `verificationMethod` array: `id` = `<did>#atproto_kem`, `controller` = the DID, `type` = `Multikey`, and `publicKeyMultibase` in atproto multikey encoding. In PLC operations this is `verificationMethods.atproto_kem`. The repo host holds the private key. It should be a dedicated keypair, not a reuse of the `#atproto` signing key. Section 7 covers how keys are created, backfilled, migrated, and rotated.

4c. Shared secret. For each MAC-bearing request, the syncer resolves the author's `#atproto_kem` key and generates a new ephemeral P-256 keypair. A new keypair is required for every request, including retries and each page of a paginated response. This key is unrelated to the credential binding key from section 1, so do not reuse that one. The syncer performs ECDH, derives the secret, and sends the ephemeral public key as a did:key in `key_share`. The repo host decodes `key_share`, performs ECDH with the author's private KEM key, and derives the same secret:

    // 32-byte x-coordinate of the shared point
    dh = ECDH(syncer_private_key, author_public_key)   // syncer
       = ECDH(author_private_key, syncer_public_key)   // repo host

    // Uncompressed points, even though did:key and multikey use the compressed form
    keys = (0x04 || syncer_pub.x || syncer_pub.y) || (0x04 || author_pub.x || author_pub.y)

    prefix = "HPKE-v1" || "KEM" || uint16be(0x0010)
    input  = prefix || "eae_prk" || dh
    info   = uint16be(32) || prefix || "shared_secret" || keys
    shared_secret = HKDF-SHA256(input, salt="", info=info, length=32)   // extract then expand

This is the DHKEM(P-256, HKDF-SHA256) shared-secret derivation of RFC 9180 §4.1, with the syncer's uncompressed public key as `enc`.

4d. Headers. The request header is a Structured Field Dictionary (`type` and `key_share` are strings, `ver` is an integer):

    Atproto-Space-Want-Mac: type="atproto-space-repo", ver=1, key_share="did:key:zDna..."

The response returns the 32-byte MAC as a byte sequence and lists the request header in Vary:

    Atproto-Space-Mac: type="atproto-space-repo", ver=1, mac=:<padded standard base64>:
    Vary: Atproto-Space-Want-Mac

The response's `type` and `ver` match the request's. A missing or malformed header, an unsupported type or version, or an invalid key is an error.

| Method          | `type`                 | `ver`              | MAC covers                                                                            |
| --------------- | ---------------------- | ------------------ | ------------------------------------------------------------------------------------- |
| getLatestCommit | `atproto-space-repo`   | commit `ver` (`1`) | the returned commit                                                                   |
| getRepo         | `atproto-space-repo`   | commit `ver` (`1`) | the commit in the STAR metadata (section 5)                                           |
| listRepoOps     | `atproto-space-repo`   | commit `ver` (`1`) | the commit, on responses that include one. Pages without a commit have no MAC header. |
| getRecord       | `atproto-space-record` | `1`                | the record's URI and CID                                                              |

listRecords, getBlob, listBlobs, and listRepos carry no MAC.

When one of these four methods is called with a space credential, the request header is required. The reference repo host answers `BadSpaceMac` (HTTP 400) if it is absent or invalid, and requires it on every listRepoOps page, including pages that turn out to have no commit. On OAuth requests for the account's own data, the header is optional, and a MAC is returned only if requested. Repo hosts serving browsers must expose the header with `Access-Control-Expose-Headers: Atproto-Space-Mac`, as the reference does. Browser clients can't read it otherwise.

4e. MAC computation. String fields are UTF-8, each prefixed with its byte length as a big-endian uint16:

    // Commit MAC
    context = "atproto-space-repo-v1"
       || uint16be(len(space)) || space
       || uint16be(len(repo))  || repo
       || uint16be(len(rev))   || rev
    mac = HMAC-SHA256(shared_secret, context || data)

    // Record MAC
    context = "atproto-space-record-v1"
       || uint16be(len(uri)) || uri          // full space record URI
    mac = HMAC-SHA256(shared_secret, context || record_cid_bytes)   // binary CID

4f. Verification by syncers. Check that the commit's `repo` and `space` match the request, then verify the MAC in constant time with that request's shared secret. Only then trust `data`. Compare it with the running set hash after the final listRepoOps page, or with the digest of a fully streamed STAR archive (section 5). For getRecord, check that the returned `uri` matches the request, verify the MAC, then check that the record's DRISL encoding matches the CID. If MAC verification fails, refresh the author's DID document (the KEM key may have rotated) and retry with a new ephemeral keypair. A repeated failure is a verification failure. Do not accept commits or records from space-credential reads without a verified MAC.

4g. Repo hosts. Parse the request header with a Structured Fields parser, check `type` and `ver` against the method, decapsulate with the account's KEM private key, and compute the MAC over exactly the commit or record in the response body. Set `Atproto-Space-Mac` and `Vary`. Map header and key errors to `BadSpaceMac`. An account without a KEM key can't serve MAC-bearing responses (section 7).

5. Serialize space repos as STAR archives.

getRepo now returns a STAR-lite v1 archive using the `atproto-space-repo` profile, with `application/octet-stream` encoding. Previously it returned a CAR file with a commit root, an index root, and record blocks. Its `excludeValues` parameter is removed. To heal a slightly diverged copy without a full download, use getLatestCommit, then listRecords with `excludeValues`, then getRecord for the differing records.

    [ magic | len | metadata ] [ len | path | len | record ] [ len | path | len | record ] ...

- The magic bytes are `0x2A 0x6C 0x01 0x00`. Each `len` is an unsigned varint giving the byte length of the following item. Follow the [STAR spec](https://tangled.org/microcosm.blue/star/tree/main/v1-star) for framing and parsing rules. The reference decoder rejects non-minimal varints.
- The metadata is a canonical DRISL map: `{ "$type": "atproto-space-repo", ver, repo, space, rev, data }`, which is the commit from section 4a plus `$type`. The MAC is in the `Atproto-Space-Mac` response header, not in the metadata.
- Each pair is a UTF-8 record path `{collection}/{rkey}` and that record's canonical DRISL encoding, at most 1 MiB (1,048,576 bytes). Pairs are in strict lexicographic order of the key bytes, with no duplicates, and continue until EOF. An empty repo has no pairs.

To consume an archive: validate the metadata (`$type`, commit version, and `repo` and `space` matching the request) and verify the commit MAC. Then start from an empty set hash and fold `{collection}/{rkey}/{record_cid}` for each pair, computing each record's CID from its bytes. Only once the archive has been fully read and `sha256(state)` equals `data` has the complete repo been received. Reject the entire archive on a parse error, non-canonical metadata, an exceeded length limit, a duplicate or out-of-order key, a MAC mismatch, or a digest mismatch. When replacing a local copy, remove records that are absent from the archive.

Writers: the reference PDS now refuses to write a space record whose DRISL encoding exceeds 1 MiB. Repo hosts must serve records in strict path order. Ordering by full record URI with a bytewise collation (e.g. `COLLATE "C"` in Postgres) gives the same order, because every URI in one space repo shares a prefix.

6. Deliver space-deletion notifications reliably.

The `notifySpaceDeleted` wire shape is unchanged. Space authorities now reliably deliver it to every syncer registered at the time of deletion. Retry network failures and transient HTTP statuses with backoff, stop on permanent HTTP errors, and persist pending deliveries until each one succeeds or that syncer's registration expires. Keep a record of the deletion so getSpaceCredential keeps answering `SpaceDeleted`, with or without a delegation token. The reference implementation stops pending deliveries if the space has been recreated since, because delivering them would purge the syncer's new copy. Deletion removes the authority's own repo in the space and leaves other members' repos in place. Deleting the authority's account deletes all of its spaces, and syncers learn of that from the account event.

An authority may recreate a deleted space with the same space type and `skey`. Members' remaining records then become readable again under the new space's access policy.

Syncers delete every copy of the space's data on `notifySpaceDeleted`, including derived state, and handle repeated deliveries idempotently. A syncer that missed the notification learns of the deletion when its credential renewal returns `SpaceDeleted`. A renewal that fails for any other reason says nothing about the space. If a space with the same URI is later recreated, treat it as a new space: obtain a credential, register, and resync from scratch.

7. Manage `#atproto_kem` keys for accounts.

Apply this section to repo hosts, identity and PLC tooling, account migration tools, and syncers that cache DID documents.

- New accounts: the repo host generates a dedicated P-256 KEM keypair and publishes it as `verificationMethods.atproto_kem` in the account's PLC genesis operation, alongside `atproto`.
- Existing accounts: the reference PDS backfills keys once, in the background after startup. When it holds a rotation key for an account and is that account's current PDS, it publishes the key to PLC and emits an `#identity` event. Otherwise (did:web accounts, accounts that removed the PDS rotation key, or accounts that migrated away), it stores a key that the account owner must publish themselves. Until an account has a published KEM key, syncers can't establish a shared secret for its repos, and its space-credential reads fail.
- `com.atproto.identity.getRecommendedDidCredentials` now includes `verificationMethods.atproto_kem` when the PDS holds a KEM key. When the PDS holds a KEM key, `com.atproto.identity.submitPlcOperation` rejects an operation whose `atproto_kem` doesn't match it ("Incorrect KEM key").
- Account migration tools must carry over every entry in the new PDS's recommended `verificationMethods`, not just `atproto`, when building the PLC operation. The new host generates its own KEM key during createAccount, and the migrated DID document must publish it.
- did:web and self-managed DID documents: add a `#atproto_kem` Multikey verification method using the public key from getRecommendedDidCredentials.
- Rotation: replace `#atproto_kem` in the DID document. This does not change repo revisions or digests. The reference `rotate-keys` script now also republishes the PDS's KEM key.
- Syncers: refresh cached KEM keys on `#identity` events, as they already do for signing keys, and on MAC failures (section 4f).

`@atproto/space`:

- `verifySpaceSignature` → `verifyCredentialSig(headers, keyId)`, which verifies credential use only. `isP256DidKey` is now exported.
- `createSpaceSig` / `createSpaceSigHeaders(key, { authorization, audience })`: `audience` is now required, `authorization` must use the `Atproto-Space-Credential` scheme, and the delegation-exchange variant (no audience, with `keyid`) is gone.
- `SignedCommit` → `Commit`. `CommitCtx.author` → `CommitCtx.repo`. `RepoCommit#sign` → `RepoCommit#toCommit({ space, repo, rev })`. `verifyCommit(commit, { space, repo, sharedSecret, mac })` is now synchronous and MAC-based. `defs.signedCommit` / `defs.repoIndex` → `defs.repoStarMeta`. `encodeCommitCtx`, `RepoCommit.fromIndex`, `RepoIndex`, `cidSchema`, and `isRecordPath` are removed.
- `verifyRepoCar` / `verifyRepoCarFull` → `verifyRepoStar` / `verifyRepoStarFull(chunks, { space, repo, sharedSecret, mac })`, where `chunks` is an `Iterable` or `AsyncIterable` of `Uint8Array` (for a single buffer, pass `[bytes]`). `VerifyRepoParams` was `{ space, author, didKey, expectValues }`. `VerifiedRepo.index` and `VerifiedRepo.repo` are removed. Fully consume (or dispose) the `records` iterator from `verifyRepoStar` before trusting it.
- `serializeRepo(commit, records)` now writes STAR and drops its `excludeValues` option. It no longer sorts its input: records must arrive in strict path order, and it throws mid-stream otherwise. `SerializedRecord` is now `{ collection, rkey, bytes }`, and `serializeRecord` returns that plus `cid`.
- New: `encapsulate(authorKemDidKey)`, which is async and resolves to `{ keyShare, sharedSecret }`, and `decapsulate(kemKeypair, keyShare)`. `formatWantMacHeader`, `parseWantMacHeader`, `formatMacHeader`, `parseMacHeader`, `computeCommitMac`, `verifyCommitMac`, `computeRecordMac`, `verifyRecordMac`, and `verifyRecord(record, { uri, sharedSecret, mac })`. `readStar` / `writeStar`. The errors `SpaceMacError` (code `BadSpaceMac`) and `StarParseError`. The constants `WANT_MAC_HEADER`, `MAC_HEADER`, `COMMIT_MAC_TYPE`, `RECORD_MAC_TYPE`, `RECORD_MAC_VERSION`, `MAX_RECORD_SIZE`, `STAR_MAGIC`, and `REPO_STAR_TYPE`.
- `spaceHostAud(did)` now returns `<did>#atproto_pds`. `createSpaceToken` throws if `kid` is passed for delegation tokens or credentials. `VerifySpaceTokenOpts.getSigningKey` is now `(iss, forceRefresh)`, without `kid`.

`@atproto/crypto`: `hkdfSha256(ikm, info)` (expand-only) → `hkdfSha256(ikm, salt, info, length)` (full RFC 5869 extract-and-expand). This changes the output for the same inputs, so audit any direct callers. `P256Keypair#ecdh(publicKey)` is new.

`@atproto/car`: now exports `createBytesReader`, `BytesReader`, and `encodeVarInt`.

`@atproto/api` generated types: `ComAtprotoSpaceDefs.SignedCommit`, `isSignedCommit`, and `validateSignedCommit` → `Commit`, `isCommit`, and `validateCommit`. Other generated types follow the Lexicon changes listed under Sources.

For a worked example of the syncer's request flow, see the `SpaceCredential` test helper in the implementation's `packages/pds/tests/_space.ts`. It signs each request, encapsulates against the author's `#atproto_kem` key, sets `Atproto-Space-Want-Mac`, and verifies commits against the response MAC.

10. Verify and report.

Validate the changed surface in proportion to what this project owns. For a small app or dependency-only update, run its available build/typecheck and focused tests or smoke check of the existing flow. Do not build an upstream protocol test suite, add a test framework, or provision server infrastructure solely for this migration.

For projects implementing affected protocol behavior themselves, choose regression tests for those changes from:

- Credential requests: body-based requests with and without a delegation token. A non-P-256 `credentialKid`. `InvalidDelegationToken` for bad, replayed, wrong-audience, or wrong-subject tokens. `SpaceNotFound` for a non-public space without a token. `SpaceDeleted` with and without a token. Acceptance of a valid but unrequired assertion.
- Credential use: the new scheme, label, and tag. A missing or wrong `tag`. Case-insensitive scheme recognition with a byte-exact signature base. Rejection of the old scheme. Padded and unpadded base64.
- Token audiences: `#atproto_pds` audiences and exactly `#atproto` `kid` values.
- MACs: commit and record MAC vectors. A wrong secret, repo, space, URI, or CID. A missing or malformed header, or the wrong type or version, with a space credential. An optional header on OAuth requests. listRepoOps pages with and without a commit. `Vary` and `Access-Control-Expose-Headers`. Retry after KEM key rotation.
- STAR: round-trip, empty repo, out-of-order or duplicate keys, oversized records, a truncated archive, and a digest mismatch.
- Deletion: deletion retries and permanent failures, expiry with the registration, cancellation on recreation, and idempotent syncer purge.
- KEM keys: key publication at account creation, backfill, `submitPlcOperation` key checks, and migration tooling that preserves `atproto_kem`.

This is a menu, not a required suite for every project.

Apply schema/state migrations only where this project owns affected persisted state, and regenerate only bindings it maintains, using its normal tooling. Audit already-applied migrations rather than assuming replacing a migration file upgrades an existing database. Run applicable existing checks. Finish with a concise summary of what applied, exact dependency versions changed, validation results, and any necessary migration steps or blockers. Group irrelevant requirements briefly; a no-change result with evidence is valid. Stop once the project's existing functionality is compatible.
